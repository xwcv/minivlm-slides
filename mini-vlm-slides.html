学习原则：不追求绝对正确率，重在理解 VLM 的基础知识与「用 VLM 解决实际问题」的范式。

建议的学习姿势：每一页都问自己 —— 这一步的输入是什么、输出是什么、谁在学习？

为什么用 VLM 做这三个任务？

传统计算机视觉

一个任务训练一个专用模型：

  • 分类：CNN + softmax 分类头
  • 检测：专门的检测头输出框
  • 问答：又一套融合模型

换任务 = 换结构、重新训练。

VLM 范式

一个模型 + 一段自然语言指令，通过"生成文本"统一完成所有任务。换任务 = 换 prompt，或微调同一份数据格式。

任务被统一为「图像 + 文本 → 文本」的条件生成

  • 模型可零样本/少样本迁移到新任务：改 prompt 即可，不必重训一个"头"；
  • 输出是自由文本，因此答案可解释、格式可自定义（甚至输出坐标）；
  • 代价：推理比专用小模型慢，输出格式需要约束与解析。

01 实验目标课程设计任务书（总览）

任务输入 → 输出数据集构建评测指标
图像分类 图像 + "图中主体属于哪个类别？" → 类别名 选定 5~10 个类别，每类 ≥50 张图像，整理为 (图像, 类别) 对 Accuracy（归一化后精确匹配）

  • 统一底座：所有任务都在 minimind-v 上完成（先推理体验，再微调提升）；
  • 必须产出：数据集（含构建脚本与说明）、微调权重、评测脚本与结果、实验报告；
  • 鼓励对比实验：微调前 vs 微调后、不同 prompt、不同冻结策略。

01 实验目标整体实验流程：一条五步走 pipeline

  • 先建零样本基线再微调 —— 没有基线就无法回答"微调有没有用、有多大用"；
  • test 集只在第 ④ 步使用一次，中间调参只看 val —— 这是机器学习的基本纪律。

01 实验目标数据集构建：四个通用要求

① 来源与规模

可从公开数据集抽样（CIFAR / ImageNet 子集、VQA v2 子集、Pascal VOC / COCO / RefCOCO 子集），也可自行拍摄收集。规模不求大：每任务 100~500 条即可跑通完整流程。

② 划分

train / val / test 按 8:1:1 划分，按图像去重（同一张图不要同时出现在 train 和 test）。test 绝不参与训练与调参。

③ 格式：与 minimind-v 对齐

整理为 conversations（对话 JSON 字符串）+ image_bytes（JPEG 二进制）两列，存为 parquet，与仓库 sft_i2t.parquet 完全一致：

[
  {"role": "user", "content":
   "<image>\n图中主体属于哪个类别？"},
  {"role": "assistant", "content": "金毛寻回犬"}
]

④ 质量控制

标注一致性（同类问题同类表述）、类别均衡、剔除模糊/歧义样本；写明标注规范是报告的一部分。可用强模型（GPT-4o 等）生成初稿再人工校对，但要在报告中说明。

01 实验目标示例①：分类数据集长什么样

(图像, 类别) 对 —— 每类 ≥50 张，类别均衡

两种可选来源：

  • 公开数据集抽样：CIFAR-10（10 类、32×32）每类抽 50~100 张，最省事；
  • 自选场景：如"校园里的 5 类物体"（自行车/外卖柜/猫/共享单车/教学楼），自己拍摄，更有成就感也更适合写报告。

转成指令格式（用于微调）：

{"role": "user", "content":
  "<image>\n图中主体属于以下哪个类别？只回答类别名。\n[猫, 狗, 汽车, 飞机, 马, 船]"}
{"role": "assistant", "content": "狗"}

注意：把候选类别写进 prompt，评测时答案空间封闭，匹配更容易 —— 这是分类任务降低解析失败率的技巧。

01 实验目标示例②：问答数据集长什么样

围绕每张图设计 2~4 个问题

问题类型问题参考答案
属性图中的狗是什么颜色的？棕色 / 金黄色
计数图中有几只狗？一只
空间关系太阳在狗的什么方位？右上方 / 头顶
场景推断这张照片大概是什么天气？晴天
  • 问题类型要覆盖：属性、计数、空间关系、场景推断各占一些 —— 小模型在计数/空间上明显更差，按类型分别统计准确率是报告的好素材；
  • 每题给 1~3 个参考答案（容忍同义表述）；
  • 可先用强模型生成初稿，再人工校对（体验"数据蒸馏"流程）。

01 实验目标示例③：检测数据集长什么样

dog

用 Labelme / CVAT 标注边界框

标注 → 指令对的转换：

# 标注文件（Labelme 输出）
{"label": "dog",
 "points": [[86.5, 109.4], [162.6, 234.5]],   # 像素坐标

{"role": "assistant", "content": "[0.298, 0.404, 0.561, 0.865]"}
  • 多目标图像：一条样本可在答案里输出多个框 + 类别；
  • 问句引用文本描述（"找出穿红衣服的人"）就是视觉定位（Grounding）任务的标准形式。

01 实验目标评测指标①：分类 Accuracy 与混淆矩阵

计算步骤：

  1. 收集模型对每个 test 样本的输出文本；
  2. 归一化：去空格/标点、统一大小写、同义词映射（"小狗"→"狗"）；
  3. 与真值标签精确匹配，统计正确数。

Accuracy = 预测正确数 / 总样本数

输出无法解析出类别名的样本要单独计数：format failure rate（格式失败率），它反映了模型"听懂格式要求"的程度。

混淆矩阵：错误结构一目了然

绿色对角线 = 预测正确；红色块揭示"猫↔狗"最易混淆

01 实验目标评测指标②：问答（开放答案怎么打分？）

Exact Match

归一化后与参考答案完全一致得 1 分，否则 0 分。

✅ 简单客观
❌ 太严苛："一只狗" vs "1 只小狗" 算错

VQA-Acc（经典定义）

VQA 数据集让 10 个人标注同一题，模型答案被越多人认同分越高：

Acc = min(1, 认同人数 / 3)

单人标注场景可用多个参考答案近似。

实用替代方案

关键词命中率：参考答案的关键词是否出现在生成中；

人工评分：抽样按 0 / 0.5 / 1 打分，两人背对背评分并报告一致性。

不管用哪个指标，都必须做的一件事：按问题类型分桶统计

属性 90% / 计数 40% / 空间关系 55% / 场景推断 75% —— 这样的分桶结果远比一个总的 65% 有信息量，也最能体现你对模型的理解。

01 实验目标评测指标③：IoU 与 Acc@IoU≥0.5

IoU = 黄色交集面积 ÷ 两框并集面积

IoU = Area(预测 ∩ 真值) / Area(预测 ∪ 真值)

  • IoU = 1：完美重合；IoU = 0：完全不相交；
  • 常用判定阈值：IoU ≥ 0.5 即认为"检测正确"（grounding 任务标准口径）；
  • 报告两个数：Acc@IoU≥0.5（定位正确的样本比例）与平均 IoU（定位精细程度）；
  • 坐标解析失败（模型没输出 4 个数）单独计数 —— 与分类的 format failure 同理。

直觉校准

两个"看起来差不多、都框住了狗"的框，IoU 通常只有 0.6~0.8 —— IoU 比人眼直觉严格。所以 65M 小模型拿到 0.3 以上的 Acc@0.5 就值得肯定。

前置知识

分类、问答、目标检测：任务定义 · 数据集 · 经典模型

本讲路线：三个任务各自"解决什么问题、用什么数据、模型怎么演进" → 传统方法的天花板在哪里 → 为什么需要 VLM

02 前置知识 · 图像分类任务定义：整张图 → 一个标签

f：图像 → C 个预定义类别之一

  • 单标签分类：每张图恰属一类（本课程设计采用）；多标签：一张图可同时有多个标签；
  • 传统做法：模型最后接一个 softmax 分类头，输出 C 维概率分布，取 argmax；
  • 评测：Top-1 Acc（最高概率类命中）、Top-5 Acc（前 5 高概率中含真值，ImageNet 常用）。

关键认知

分类是输出空间最小、最容易评测的视觉任务 —— 它也是检验任何新模型"能不能看图"的第一块试金石。

02 前置知识 · 图像分类经典数据集：难度逐级递增

MNIST（1998）

手写数字，28×28 灰度，10 类，6 万训练图。深度学习的"Hello World"。

CIFAR-10/100（2009）

32×32 彩色自然图像，10/100 类，5 万训练图。小尺寸、类内差异大，课程设计抽样的首选。

ImageNet（2009）

128 万张图、1000 类、高分辨率。2012 年 AlexNet 在此夺冠，引爆深度学习革命；至今仍是预训练的事实标准。

ILSVRC 竞赛推动了 AlexNet → VGG → GoogLeNet → ResNet 的军备竞赛。

规律：数据集规模每上一个台阶，就催生一代新模型 —— "数据成就模型"在视觉领域反复上演，VLM 时代同样如此。

02 前置知识 · 图像分类模型演进：一条 25 年的时间线

  • 残差连接（y = F(x) + x）解决了深层网络梯度消失，是今天所有大模型的基础设施；
  • ViT 证明：把图像切成 patch 当 token 处理，纯 Transformer 也能称霸视觉 —— 为 VLM 埋下伏笔；
  • CLIP 证明：用 4 亿图文对做对比学习，视觉特征可以天然"懂语言"，不用训练就能分类。

02 前置知识 · 图像分类插页：CNN 的直觉（为理解 ViT 做铺垫）

  • 卷积：一个小窗口（卷积核）在图像上滑动，检测局部模式（边缘→纹理→部件→物体）；
  • 池化/下采样：逐步压缩尺寸，让越深的层"看"到越大的视野、越抽象的概念；
  • CNN 内置了两个假设：局部性（相邻像素相关）与平移不变性（猫在左上角和右下角都是猫）。

ViT 的颠覆

ViT 放弃这两个假设：把图像切成 16×16 的 patch，拉平成 token 序列丢给 Transformer，让注意力自己去学"哪些 patch 相关"。数据足够多时，学得比人工假设更好 —— 这也统一了图像与文本的处理方式。

02 前置知识 · 视觉问答VQA：看得懂，还要答得对

图中有几只狗？
一只。
天气怎么样？
晴天，太阳很大。

任务定义：给定图像 + 关于图像的自然语言问题，输出答案。它是视觉理解 + 语言推理的联合测试。

难点：

  • 问题决定"看哪里"—— 问颜色要看物体表面，问数量要数清楚；
  • 语言先验陷阱：模型可能不看图，凭"狗通常是棕色的"来猜 —— 好数据集（如 VQA v2）专门设计对抗样本惩罚这种行为；
  • 答案开放，评测比分类难（见第 ① 讲指标设计）。

经典数据集：

  • VQA v1/v2：COCO 图像 + 人工问答，领域基准；
  • GQA：基于场景图的组合推理问答（"大狗左边的东西是什么颜色？"）；
  • TextVQA / DocVQA：需要读懂图中文字才能回答。

02 前置知识 · 视觉问答VQA 方法演进：从"拼接特征"到"统一生成"

  • VQA 是 VLM 最自然的应用形态 —— minimind-v 的 SFT 数据本身就是百万级图文问答；
  • 课程设计的问答任务重点不在"让模型会问答"（它本来就会一点），而在数据集构建与评测设计。

02 前置知识 · 目标检测任务定义：有什么 + 在哪里

dog 0.93
sun 0.87

输出：每个目标的 框 + 类别 + 置信度

  • 边界框：(x, y, w, h) 或 (x1, y1, x2, y2)，定位目标的矩形；
  • IoU：预测框与真值框的交并比（第 ① 讲已图解），衡量定位质量；
  • AP / mAP：按置信度排序画 Precision-Recall 曲线，曲线下面积为 AP，各类别均值为 mAP —— 检测领域主指标；
  • NMS：非极大值抑制，同一目标的多个重叠框只留置信度最高的。

经典数据集：

  • Pascal VOC：20 类、~1 万图，小而经典（适合课程设计抽样）；
  • MS COCO：80 类、33 万图，检测领域的"ImageNet"。

02 前置知识 · 目标检测检测模型谱系：五代演进

路线代表模型核心思想特点
两阶段R-CNN → Fast/Faster R-CNN先提候选区域（Region Proposal），再逐区域分类+回归框精度高、速度慢
一阶段YOLO 系列 / SSD图像划网格，每个网格直接预测框与类别快，可实时
Anchor-freeFCOS / CenterNet抛弃预设锚框，直接预测中心点与尺寸设计更简洁
TransformerDETR 系列把检测看成集合预测：object query 与图像做注意力，二分匹配免 NMS端到端、免手工后处理
开放词汇Grounding DINO / VLM用文本描述指定要检测的目标（"穿红衣服的人"）类别不再封闭

为什么传统检测器不够用？

类别集合在训练时固定：COCO 检测器只会检测那 80 类，想检测"外卖柜"就得重新收集数据训练。而 VLM 让「用语言描述任意目标 → 输出它的位置」成为可能 —— 这正是本课程设计检测任务的切入点（视觉定位 / Grounding）。

02 前置知识 · 小结三个任务的关系：理解深度的阶梯

是什么？整图 → 一个标签 目标检测 有什么 + 在哪里？多个框 + 类别 视觉问答 关于图像的任意问题：理解与推理

分类

粒度最粗，输出空间最小，评测最容易。

检测

多了定位维度，评测要同时看类别对与位置准（IoU）。

问答

输出空间开放，涉及计数、属性、关系、常识，评测最难标准化。

传统方法：三个任务三套模型。VLM：一个模型、三种 prompt —— 输出都是文本序列。这条由易到难的阶梯，也正是课程设计三个任务的推荐完成顺序。

VLM 基础知识

Transformer · VLM 架构 · 训练方法 · 改进方向

本讲路线：token 是什么 → 注意力 → Transformer → LLM 如何"学习" → 图像如何变成 token → 三段式 VLM 架构 → 怎么训练

03 VLM 基础 · Transformer第一步：机器不认识文字，只认识向量

token（词元）：把文本切成的最小处理单元（可以是字、子词或词）。

"这只狗很可爱"
→ [这, 只, 狗, 很, 可, 爱]
→ [1024,  215, 3881, 77,  930,  452]   # 查表得到 id

embedding（嵌入）：每个 id 查表得到一个高维向量（如 768 维），语义相近的词向量也相近 —— 语义被"装进"了几何空间。

文本序列 → id 序列 → 向量矩阵 (seq_len × 768)

记住这个画面：模型处理的一切都是"一排向量"。后面我们会看到 —— 图像也可以变成这样一排向量，这就是 VLM 的全部秘密。

03 VLM 基础 · Transformer自注意力：让每个词"看见"其他词

读这句话："这只狗没有去追那只猫，因为它吃饱了。"

"它"指谁？人一眼知道是狗。机器怎么知道？—— 让"它"这个 token 去查询句子里所有 token，算一算和谁关系最大。

自注意力（Self-Attention）：序列中每个 token 都与所有 token 计算相关性权重，再按权重把大家的信息加权混合进来，从而建模长程依赖。

"因果掩码"：生成式模型里，每个位置只能看它左边的 token（不许偷看未来），保证逐字生成的自回归特性。

"它"这一行：狗 的格子最亮 → 指代消解自动完成

03 VLM 基础 · Transformer注意力怎么算：Q、K、V 三个角色

每个 token 的向量被线性变换成三份，各司其职：

  • Q（Query 查询）："我想找什么"
  • K（Key 键）："我是什么"（被检索的名片）
  • V（Value 值）："我携带的信息"

用 Q 和所有 K 算相似度 → softmax 归一化成权重 → 对 V 加权求和：

Attention(Q,K,V) = softmax(QKᵀ/√d) · V

除以 √d 防止内积过大导致 softmax 饱和；所有 token 的 Q/K/V 拼成矩阵，一次矩阵乘法完成全部计算（高度并行）。

Multi-Head Attention

把向量切成 h 份，并行做 h 组注意力：一组关注语法、一组关注指代、一组关注位置…… 各学各的关系，最后拼接 —— 相当于"多角度互相看"。

一个 Transformer Block

Multi-Head Attention → 残差+LayerNorm → FFN（两层 MLP）→ 残差+LayerNorm。把 N 个 block 堆起来（minimind 是 8 层），就是完整模型。残差连接让深层堆叠可训练（ResNet 的遗产）。

为什么它能统一一切？

输入只要求是任意 token 序列 —— 文本 token、图像 patch token、语音 token 一视同仁。这就是 VLM 架构的地基。

03 VLM 基础 · TransformerLLM 如何学习：下一个 token 预测

训练目标：给前面所有 token，预测下一个。海量文本上的这一简单目标，逼出了语言与世界知识：

P(x₁..xₙ) = ∏ᵢ P(xᵢ | x₁..xᵢ₋₁)

推理（生成）：一个 token 一个 token 往外蹦，直到输出结束符：

输入: "这只狗很"      → 模型: 可
输入: "这只狗很可"    → 模型: 爱
输入: "这只狗很可爱"  → 模型: <eos> 停止

两阶段训练：

阶段数据学到什么
预训练 Pretrain海量无标注文本语言能力 + 世界知识
指令微调 SFT(指令, 回答) 对听懂人话、按指令回答

「LLM 与"语言"关系不大，更确切的名字是自回归 Transformer —— 一种建模 token 流的通用技术。token 可以代表文本、图片、音频、动作…… 任何东西。」

这是 VLM 的思想根源：图像只要能变成 token 序列，就能交给同一个 Transformer 做同样的"下一个 token 预测"。

03 VLM 基础 · 架构核心比喻：图像是一门外语，我们需要一本词典

minimind-v 作者的精彩比喻：

对 LLM 来说，图像就像一门从未见过的"外语"。要让它理解图片，只需两件事：
1️⃣ 一本擅长翻译图片的「外语词典」—— Visual Encoder，把图像翻译成 LLM 能理解的"语言"（视觉 token）；
2️⃣ 微调 LLM，让它和这本"词典"度过磨合期，学会理解翻译过来的视觉信息。

音频、视频、点云…… 任何模态接入 LLM 都是同样的配方 —— 这就是为什么 VLM 架构如此通用。

03 VLM 基础 · 架构VLM 的通用架构：三段式

LLaVA、Qwen-VL、MiniCPM-V、InternVL、minimind-v —— 都是这个骨架，差异在组件选型、数据与训练策略

03 VLM 基础 · 架构① 视觉编码器：图像怎么变成 token

一张图 = 64 个视觉 token（和"一排词向量"长得一样！）

过程：

  1. 图像 resize 到 256×256，按 32×32 切成 8×8 = 64 个 patch；
  2. 每个 patch 拉平 + 线性映射成一个向量，加上位置编码；
  3. 64 个向量序列送进 ViT 做自注意力（patch 之间互相"看"）；
  4. 取 encoder 层输出：64 × 768 的特征矩阵。

回头看上一讲的伏笔

CNN 靠"局部性"假设，ViT 靠注意力自己学 patch 间关系 —— 而 VLM 直接把 ViT 的输出当作一排 token。图像和文本在形式上被统一了。

03 VLM 基础 · 架构这本"词典"从哪来：CLIP 的图文对比学习

对比损失 InfoNCE：配对的图文向量靠近，不配对的远离

CLIP（2021, OpenAI）：

  • 用 4 亿 (图像, 文本) 对训练图像编码器 + 文本编码器，各自输出一个向量；
  • 训练后，两个编码器的输出落在同一个语义空间 —— 图像向量和"它的描述"的文本向量天然接近；
  • 副产品：零样本分类 —— 把 "a photo of a {类别}" 的文本向量和图像向量比相似度即可分类，不需要分类头、不需要训练。

为什么 VLM 都爱用 CLIP 系编码器？

特征空间天然与语言对齐（训练时就见过文本），投影层学起来事半功倍；表征通用、开放词汇；开箱即用、冻结即可，省去昂贵的视觉预训练。

03 VLM 基础 · 架构SigLIP：CLIP 的高效改进版（minimind-v 的选择）

改进点：

  • CLIP 用 softmax 对比损失：需要全局归一化，大 batch 才稳定；
  • SigLIP 改为 sigmoid 逐对二分类损失：每对图文独立判断"配/不配"，小 batch 也稳定，训练更高效；
  • SigLIP2 进一步加入自蒸馏、多分辨率等技巧，是当下 VLM 最常用的视觉骨干之一。

minimind-v 的具体选型：siglip2-base-p32-256-ve

  • ViT-B/32 架构，~95M 参数，全程冻结，只做特征提取；
  • 256×256 输入 → 64 个 patch token → 输出 64×768 特征；
  • 只取 encoder 层输出（不需要它最终的对比学习嵌入向量）。

一个值得想的问题

SigLIP 训练的目标是"整图 ↔ 整段文本"的对齐，输出里每个 patch token 却携带着局部信息。VLM 复用它的 patch 级特征而不是整图向量 —— 为什么这样也行得通？（提示：注意力让 patch 之间交换过信息，且投影层与后续微调会进一步适配。）

分辨率是硬约束

256×256、64 个 token 意味着每个 token 管 32×32 像素的区域。小目标、图中文字在这个尺度下已经模糊 —— 这直接限制了检测定位精度与 OCR 能力（后面改进方向会再遇到它）。

03 VLM 基础 · 架构② 投影层：把视觉特征"对齐"进语言空间

Projector 的职责：把视觉 token 的维度与分布映射到文本 embedding 所在的空间，让两种 token 可以在同一空间里被同一个 Transformer 处理 —— 这一步叫跨模态特征对齐。

方案演进：

  • LLaVA-1：单层线性变换 —— 简单有效；
  • LLaVA-1.5：2 层 MLP（Linear→GELU→Linear）—— 更强，成为事实标准；
  • BLIP-2：Q-Former，用少量可学习 query 把视觉信息压缩成固定数量的 token；
  • minimind-v：LayerNorm + 2 层 MLP（同 LLaVA-1.5 方案），~1M 参数。

Projector 参数极少，却是 VLM 里第一个被训练、且必被训练的模块。

03 VLM 基础 · 架构③ 拼在一起：占位符替换机制（最关键的一步）

minimind-v 中这段核心逻辑（找到占位符位置、填入视觉特征）连同训练适配 < 50 行代码 —— 读源码时请一定找到它

03 VLM 基础 · 训练冻结策略的权衡（课程设计的重要实验变量）

03 VLM 基础 · 改进代表性 VLM 与主要改进方向

模型特点
CLIP / SigLIP图文对比学习，提供视觉编码器与零样本能力
BLIP-2Q-Former 压缩视觉 token 数
LLaVA / 1.5线性/MLP 投影的极简范式，教学首选
Qwen-VL 系列支持检测框、OCR 等定位类输出
LLaVA-NeXT动态分辨率 + 图像切片（tile）
MiniCPM-V / InternVL小尺寸高性能代表

主要改进方向（可作报告"展望"素材）：

  • 更高分辨率：固定 256² 看不清细节 → 动态分辨率、tile 切片编码；
  • 更强视觉编码器：更细粒度特征、多编码器融合；
  • 视觉 token 压缩：缩短序列、降低推理成本；
  • 视觉定位 Grounding：输出坐标，打通检测/分割类任务（我们任务三的同款思想）；
  • 多图与视频理解：时序与跨图推理；
  • 数据质量：GPT-4o 等强模型合成高质量指令数据（蒸馏）。

共同点：架构创新空间在收窄，数据与训练策略成为拉开差距的关键 —— 这也是课程设计把"数据集构建"放在目标第一位的原因。

基于 VLM 实现三大任务

统一范式：图像 + 指令 → 文本生成

本讲路线：统一范式 → 分类 / 问答 / 检测逐个落地（prompt 设计 + 解析 + 评测）→ 混成一份 SFT 数据

04 实现方式统一范式：一切皆生成

VLM 的输出永远是一段文本。三个任务的区别，只在于我们要求它生成什么内容、用什么格式：

任务Prompt 示例期望输出（文本）解析与评测
分类 "图中主体属于以下哪个类别？[猫, 狗, 汽车…] 只回答类别名。" 金毛寻回犬 字符串归一化 → 精确匹配 → Accuracy
问答 "图中有几个人？他们在做什么？" 两个人，在草地上野餐。 EM / 关键词 / 人工评分
检测 "找出图中的狗，输出 [x1,y1,x2,y2]，0~1 归一化。" [0.12, 0.34, 0.56, 0.78] 正则抽坐标 → 与真值算 IoU

关键① Prompt 设计

明确输出格式与取值范围，显著降低解析失败率（可作对比实验）。

关键② 输出解析

写鲁棒的解析器（正则/格式约束），统计 format failure rate。

关键③ 微调对齐

把任务数据转成指令格式做 SFT，让模型"学会"按格式回答 —— 提升最大的手段。

04 实现方式 · 分类路线 A：零样本分类（不训练，先跑通）

做法：直接设计 prompt，把候选类别写进去，让模型"做选择题"：

<image>\n图中主体属于以下哪个类别？
[飞机, 汽车, 鸟, 猫, 鹿, 狗, 青蛙, 马, 船, 卡车]
只回答类别名称。

为什么给候选列表？答案空间封闭 → 解析容易、评测客观；不给列表则是"开放分类"，更贴近真实使用但更难评测。两者都可以试，写进报告对比。

Prompt 工程小实验（报告素材）

  • 有/无候选列表
  • 中文 vs 英文 prompt
  • "只回答类别名" vs 不加约束

观察零样本准确率与格式失败率对措辞的敏感度 —— 小模型尤其敏感。

预期现象

minimind-v 的 SFT 数据是开放描述与问答，没专门学过"封闭式分类"，所以零样本分类可能：答对但啰嗦（"这是一只狗"）、或干脆不选列表里的词 —— 这正是微调要解决的问题。

04 实现方式 · 分类路线 B：微调分类（把"分类头"藏进生成里）

微调数据：答案固定为类别名的指令对（第 ① 讲已展示格式）。

评测流程：

报告里要做的对比：

  • 零样本 vs 微调后 Accuracy（预期大幅提升）；
  • 混淆矩阵：哪几类最容易混（如 猫↔狗）；
  • 微调后回答是否变得"守规矩"（格式失败率 → ~0）。

思考点（写进报告）

生成式分类 vs 传统 softmax 分类头：本质区别是什么？生成式的优势（开放类别、可解释、多任务共享一个模型）与代价（推理慢、格式不可控）分别是什么？

04 实现方式 · 问答问答：VLM 的"主场"，重点在数据与评测

minimind-v 开箱即可问答（SFT 数据本身就是百万级图文问答）。本任务的重点是建一个属于你自己的评测集：

  • 选定一个垂直场景（校园照片 / 交通场景 / 商品图…），围绕图像设计问题；
  • 问题类型覆盖：属性（什么颜色）、计数（有几个）、空间关系（A 在 B 左边吗）、场景推断（大概什么时间）；
  • 每题 1~3 个参考答案，≥100 条；
  • 可用强模型生成初稿再人工校对 —— 体验"数据蒸馏"。

是否微调自选：可以用自己场景的数据做一轮 SFT，观察领域适配效果。

评测：EM / 关键词命中率 / 人工评分（0/0.5/1）+ 按问题类型分桶。

典型错误模式（错误分析框架）

模式表现可能原因
幻觉描述图中不存在的内容语言先验压过视觉证据
语言先验不看图凭"常识"回答视觉 token 权重不足
重复啰嗦句子反复复读小模型解码常见病症
答非所问不遵循指令指令理解能力弱

给每类错误配 1~2 个截图案例，是报告最出彩的部分。

04 实现方式 · 检测检测：坐标也是文本，让模型"说出"框

核心思想：边界框的 4 个坐标，不过是 4 个数字 —— 数字也是 token，模型可以像说话一样把框"说"出来（Qwen-VL 与各类 Grounding 模型的标准做法）。

用户: <image>\n找出图中的狗，输出边界框，
格式 [x1,y1,x2,y2]，0~1 归一化。
助手: [0.122, 0.341, 0.563, 0.782]
  • 坐标归一化到 0~1（或 0~999 整数），与图像分辨率解耦；
  • 多目标：输出多个框，框与类别名配对；
  • 此即视觉定位（Visual Grounding）：给文本描述，定位对应目标。
pred [0.20,0.32,0.66,0.90]
gt [0.26,0.38,0.62,0.86]

预测框 vs 真值框 → 算 IoU → Acc@IoU≥0.5

预期与心态

65M 小模型 + 256² 低分辨率，坐标不可能很准。看到"微调后 IoU 显著上升、框大致落在目标区域"就是成功。想一想：64 个视觉 token、每个管 32×32 像素，这个粒度如何限制定位精度？

04 实现方式收尾：把三个任务混成一份 SFT 数据

# 每条样本 = conversations(json) + image_bytes(图像二进制)，存为 parquet

# 分类样本
[{"role": "user",      "content": "<image>\n图中主体属于哪个类别？只回答类别名。"},
 {"role": "assistant", "content": "狗"}]

# 问答样本
[{"role": "user",      "content": "图中有几个人？<image>"},
 {"role": "assistant", "content": "两个人，正坐在草地上。"}]

# 检测样本
[{"role": "user",      "content": "<image>\n定位图中的狗，输出 [x1,y1,x2,y2] 归一化坐标。"},
 {"role": "assistant", "content": "[0.122, 0.341, 0.563, 0.782]"}]
  • 同一模型、一次训练，学会三种"回答格式" —— 这就是 VLM 多任务范式的魅力；
  • 建议混入少量通用问答/描述数据（防止过拟合、保持通用能力）—— 类比 minimind-v 在 SFT 中混入 23 万条纯文本对话的做法；
  • 对比实验：单任务分别微调 vs 三任务混合微调，观察相互促进还是干扰。

05 实战认识我们的实验平台：minimind 与 minimind-v

minimind（语言模型基座）

孪生项目 jingyaogong/minimind：从 0 训练极小 LLM 的开源实现，含 tokenizer、预训练、SFT、LoRA、DPO 全流程。本课程使用其训练好的 llm_768.pth（768 隐藏维、8 层，~64M 参数）作为 VLM 的语言主干。

minimind-v（视觉拓展）

在 minimind 之上加视觉编码器 + 投影层，核心算法改动 < 50 行。65M 可训练参数（GPT-3 的 1/2600），单张 3090 上 SFT 约 2 小时、成本约 3 元。

为什么选它做课程设计？

  • 代码极简、无框架黑盒：PyTorch 原生，每个环节都能读懂、能改；
  • 算力门槛低：单卡 24G 可训练；
  • 全流程自洽：数据格式 → 训练 → 推理 → WebUI 完整闭环；
  • 架构与 LLaVA 等主流 VLM 思路一致，学会它即学会一类。

型号（2026-04 版本）：dense 65M / MoE 200M-A65M；视觉编码器 SigLIP2（~95M，冻结）；投影层 MLP（~1M）。

输入端：prompt 中图像用 64 个 <|image_pad|> 占位：

文本查 embedding 后，用投影后的 64 个视觉 token 逐个替换占位符位置的 embedding，之后与纯 LLM 计算完全一致（第 ③ 讲的占位符替换图）。

请在代码里找到这三个位置（读源码作业）：

  • 视觉编码：model/ 下 VLM 类中调用 SigLIP、取 encoder 层输出（不用最终对比嵌入）；
  • 投影层：vision_proj（LayerNorm + 2 层 MLP）；
  • embedding 替换逻辑：定位 <|image_pad|> 并填入视觉特征 —— 全程 < 50 行，务必亲手读一遍并画出数据流向图。

05 实战微调要点与建议的对比实验

微调要点：

  • 基座选择：从 llm（纯语言权重）起步，或在官方 sft_vlm 上继续微调（推荐，省一轮对齐）；
  • 冻结策略：小数据微调建议 --freeze_llm 1 或 2，全参容易"洗掉"语言能力；
  • 学习率：小数据集用小 lr（1e-5 量级）+ 2~4 epoch，盯 loss 与 val 表现，警惕过拟合（训练集背下来、测试集不会）；
  • 断点续训：--from_resume 1 随时可中断恢复。

建议的对比实验（报告亮点，挑 2~3 组做扎实）：

对比项观察什么
零样本 vs 微调后格式遵循率、各任务指标跃升
freeze_llm = 0/1/2任务指标 vs 通用能力保持
不同 prompt 表述零样本性能对措辞的敏感度
单任务 vs 多任务混合任务间促进还是干扰
数据量 50/200/500数据规模的学习曲线

05 实战避坑指南：六个高频问题

模型答非所问 / 不守格式

检查 prompt 是否与训练时表述一致；微调数据里答案格式是否统一；<image> 占位符是否漏写。

微调后反而"变傻"

典型灾难性遗忘：任务数据占比过高或 lr 过大。改 --freeze_llm 1/2、混入通用对话数据、降 lr。

检测坐标完全不对

先确认输出格式正确（能解析出 4 个数）再谈精度；检查归一化约定；256² 分辨率下小目标本就难，属预期现象。

重复啰嗦 / 停不下来

小模型常见。调低 temperature、增大 repetition_penalty（如 1.2）；也是错误分析的好素材。

显存不足

减小 batch_size + 梯度累积；缩短 max_seq_len；确认视觉编码器已冻结。

数据格式踩坑

用仓库 dataset/lm_dataset.py 预览自己的 parquet 前 5 条；确认列名、role 字段、图像字节流与官方样例一致。

动机

为什么用 VLM 做这三个任务？

传统计算机视觉

一个任务训练一个专用模型：

  • 分类：CNN + softmax 分类头
  • 检测：专门的检测头输出框
  • 问答：又一套融合模型

换任务 = 换结构、重新训练。

VLM 范式

一个模型 + 一段自然语言指令，通过"生成文本"统一完成所有任务。换任务 = 换 prompt，或微调同一份数据格式。

任务被统一为「图像 + 文本 → 文本」的条件生成

  • 模型可零样本/少样本迁移到新任务：改 prompt 即可，不必重训一个"头"；
  • 输出是自由文本，答案可解释、格式可自定义（甚至输出坐标）；
  • 代价：推理比专用小模型慢，输出格式需要约束与解析。

数据集构建：四个通用要求

① 来源与规模

可从公开数据集抽样（CIFAR / ImageNet 子集、VQA v2 子集、Pascal VOC / COCO / RefCOCO 子集），也可自行拍摄收集。规模不求大：每任务 100~500 条即可跑通完整流程。

② 划分

train / val / test 按 8:1:1 划分，按图像去重（同一张图不要同时出现在 train 和 test）。test 绝不参与训练与调参。

③ 格式：与 minimind-v 对齐

整理为 conversations（对话 JSON）+ image_bytes（JPEG 二进制）两列，存为 parquet，与仓库 sft_i2t.parquet 一致：

[
  {"role": "user", "content":
   "<image>\n图中主体属于哪个类别？"},
  {"role": "assistant", "content": "金毛寻回犬"}
]

④ 质量控制

标注一致性（同类问题同类表述）、类别均衡、剔除模糊/歧义样本；写明标注规范是报告的一部分。可用强模型（GPT-4o 等）生成初稿再人工校对，但要在报告中说明。

评测指标①：分类 Accuracy 与混淆矩阵

计算步骤：

  1. 收集模型对每个 test 样本的输出文本；
  2. 归一化：去空格/标点、统一大小写、同义词映射（"小狗"→"狗"）；
  3. 与真值标签精确匹配，统计正确数。

Accuracy = 预测正确数 / 总样本数

输出无法解析出类别名的样本要单独计数：format failure rate（格式失败率），它反映模型"听懂格式要求"的程度。

混淆矩阵：错误结构一目了然

绿色对角线 = 预测正确；红色块揭示"猫↔狗"最易混淆

评测指标②：问答（开放答案怎么打分？）

Exact Match

归一化后与参考答案完全一致得 1 分，否则 0 分。

✅ 简单客观
❌ 太严苛："一只狗" vs "1 只小狗" 算错

VQA-Acc（经典定义）

VQA 数据集让 10 个人标注同一题，模型答案被越多人认同分越高：

Acc = min(1, 认同人数 / 3)

单人标注场景可用多个参考答案近似。

实用替代方案

关键词命中率：参考答案的关键词是否出现在生成中；

人工评分：抽样按 0 / 0.5 / 1 打分，两人背对背评分并报告一致性。

不管用哪个指标，都必须做的一件事：按问题类型分桶统计

属性 90% / 计数 40% / 空间关系 55% / 场景推断 75% —— 这样的分桶结果远比一个总的 65% 有信息量，也最能体现你对模型的理解。

评测指标③：IoU 与 Acc@IoU≥0.5

IoU = 黄色交集面积 ÷ 两框并集面积

IoU = Area(预测 ∩ 真值) / Area(预测 ∪ 真值)

  • IoU = 1：完美重合；IoU = 0：完全不相交；
  • 常用判定阈值：IoU ≥ 0.5 即认为"检测正确"（grounding 任务标准口径）；
  • 报告两个数：Acc@IoU≥0.5（定位正确的样本比例）与平均 IoU（定位精细程度）；
  • 坐标解析失败（模型没输出 4 个数）单独计数 —— 与分类的 format failure 同理。

直觉校准

两个"看起来差不多、都框住了狗"的框，IoU 通常只有 0.6~0.8 —— IoU 比人眼直觉严格。所以 65M 小模型拿到 0.3 以上的 Acc@0.5 就值得肯定。

02 · 图像分类

任务定义：整张图 → 一个标签

f：图像 → C 个预定义类别之一

  • 单标签分类：每张图恰属一类（本课程设计采用）；多标签：一张图可同时有多个标签；
  • 传统做法：模型最后接一个 softmax 分类头，输出 C 维概率分布，取 argmax；
  • 评测：Top-1 Acc（最高概率类命中）、Top-5 Acc（前 5 高概率中含真值，ImageNet 常用）。

关键认知

分类是输出空间最小、最容易评测的视觉任务 —— 它也是检验任何新模型"能不能看图"的第一块试金石。

手写数字，28×28 灰度，10 类，6 万训练图。深度学习的"Hello World"。

128 万张图、1000 类、高分辨率。2012 年 AlexNet 在此夺冠，引爆深度学习革命；至今仍是预训练的事实标准。

02 · 图像分类

插页：CNN 的直觉（为理解 ViT 做铺垫）

  • 卷积：一个小窗口（卷积核）在图像上滑动，检测局部模式（边缘→纹理→部件→物体）；
  • 池化/下采样：逐步压缩尺寸，让越深的层"看"到越大的视野、越抽象的概念；
  • CNN 内置了两个假设：局部性（相邻像素相关）与平移不变性（猫在左上角和右下角都是猫）。

ViT 的颠覆

ViT 放弃这两个假设：把图像切成 16×16 的 patch，拉平成 token 序列丢给 Transformer，让注意力自己去学"哪些 patch 相关"。数据足够多时，学得比人工假设更好 —— 这也统一了图像与文本的处理方式。

02 · 视觉问答

VQA：看得懂，还要答得对

图中有几只狗？
一只。
天气怎么样？
晴天，太阳很大。

任务定义：给定图像 + 关于图像的自然语言问题，输出答案。它是视觉理解 + 语言推理的联合测试。

难点：

  • 问题决定"看哪里" —— 问颜色要看物体表面，问数量要数清楚；
  • 语言先验陷阱：模型可能不看图，凭"狗通常是棕色的"来猜 —— 好数据集（如 VQA v2）专门设计对抗样本惩罚这种行为；
  • 答案开放，评测比分类难（见第 ① 讲指标设计）。

经典数据集：

  • VQA v1/v2：COCO 图像 + 人工问答，领域基准；
  • GQA：基于场景图的组合推理问答（"大狗左边的东西是什么颜色？"）；
  • TextVQA / DocVQA：需要读懂图中文字才能回答。

任务定义：有什么 + 在哪里

dog 0.93

输出：每个目标的 框 + 类别 + 置信度

  • 边界框：(x, y, w, h) 或 (x1, y1, x2, y2)，定位目标的矩形；
  • IoU：预测框与真值框的交并比（第 ① 讲已图解），衡量定位质量；
  • AP / mAP：按置信度排序画 Precision-Recall 曲线，曲线下面积为 AP，各类别均值为 mAP —— 检测领域主指标；
  • NMS：非极大值抑制，同一目标的多个重叠框只留置信度最高的。

经典数据集：

  • Pascal VOC：20 类、~1 万图，小而经典（适合课程设计抽样）；
  • MS COCO：80 类、33 万图，检测领域的"ImageNet"。

03 · Transformer

第一步：机器不认识文字，只认识向量

token（词元）：把文本切成的最小处理单元（可以是字、子词或词）。

"这只狗很可爱"
→ [这, 只, 狗, 很, 可, 爱]
→ [1024,  215, 3881, 77,  930,  452]   # 查表得到 id

embedding（嵌入）：每个 id 查表得到一个高维向量（如 768 维），语义相近的词向量也相近 —— 语义被"装进"了几何空间。

文本序列 → id 序列 → 向量矩阵 (seq_len × 768)

记住这个画面：模型处理的一切都是"一排向量"。后面我们会看到 —— 图像也可以变成这样一排向量，这就是 VLM 的全部秘密。

03 · Transformer

自注意力：让每个词"看见"其他词

读这句话："这只狗没有去追那只猫，因为它吃饱了。"

"它"指谁？人一眼知道是狗。机器怎么知道？—— 让"它"这个 token 去查询句子里所有 token，算一算和谁关系最大。

自注意力（Self-Attention）：序列中每个 token 都与所有 token 计算相关性权重，再按权重把大家的信息加权混合进来，从而建模长程依赖。

"因果掩码"：生成式模型里，每个位置只能看它左边的 token（不许偷看未来），保证逐字生成的自回归特性。

"它"这一行：狗 的格子最亮 → 指代消解自动完成

03 · Transformer

注意力怎么算：Q、K、V 三个角色

每个 token 的向量被线性变换成三份，各司其职：

  • Q（Query 查询）："我想找什么"
  • K（Key 键）："我是什么"（被检索的名片）
  • V（Value 值）："我携带的信息"

用 Q 和所有 K 算相似度 → softmax 归一化成权重 → 对 V 加权求和：

Attention(Q,K,V) = softmax(QKᵀ/√d) · V

除以 √d 防止内积过大导致 softmax 饱和；所有 token 的 Q/K/V 拼成矩阵，一次矩阵乘法完成全部计算（高度并行）。

Multi-Head Attention

把向量切成 h 份，并行做 h 组注意力：一组关注语法、一组关注指代、一组关注位置…… 各学各的关系，最后拼接 —— 相当于"多角度互相看"。

一个 Transformer Block

Multi-Head Attention → 残差+LayerNorm → FFN（两层 MLP）→ 残差+LayerNorm。把 N 个 block 堆起来（minimind 是 8 层），就是完整模型。残差连接让深层堆叠可训练（ResNet 的遗产）。

为什么它能统一一切？

输入只要求是任意 token 序列 —— 文本 token、图像 patch token、语音 token 一视同仁。这就是 VLM 架构的地基。

03 · Transformer

LLM 如何学习：下一个 token 预测

训练目标：给前面所有 token，预测下一个。海量文本上的这一简单目标，逼出了语言与世界知识：

P(x₁..xₙ) = ∏ᵢ P(xᵢ | x₁..xᵢ₋₁)

推理（生成）：一个 token 一个 token 往外蹦，直到输出结束符：

输入: "这只狗很"      → 模型: 可
输入: "这只狗很可"    → 模型: 爱
输入: "这只狗很可爱"  → 模型: <eos> 停止

两阶段训练：

阶段数据学到什么
预训练 Pretrain海量无标注文本语言能力 + 世界知识
指令微调 SFT(指令, 回答) 对听懂人话、按指令回答

「LLM 与"语言"关系不大，更确切的名字是自回归 Transformer —— 一种建模 token 流的通用技术。token 可以代表文本、图片、音频、动作…… 任何东西。」

这是 VLM 的思想根源：图像只要能变成 token 序列，就能交给同一个 Transformer 做同样的"下一个 token 预测"。

① 视觉编码器：图像怎么变成 token

一张图 = 64 个视觉 token（和"一排词向量"长得一样！）

过程：

  1. 图像 resize 到 256×256，按 32×32 切成 8×8 = 64 个 patch；
  2. 每个 patch 拉平 + 线性映射成一个向量，加上位置编码；
  3. 64 个向量序列送进 ViT 做自注意力（patch 之间互相"看"）；
  4. 取 encoder 层输出：64 × 768 的特征矩阵。

回头看上一讲的伏笔

CNN 靠"局部性"假设，ViT 靠注意力自己学 patch 间关系 —— 而 VLM 直接把 ViT 的输出当作一排 token。图像和文本在形式上被统一了。

这本"词典"从哪来：CLIP 的图文对比学习

对比损失 InfoNCE：配对的图文向量靠近，不配对的远离

CLIP（2021, OpenAI）：

  • 用 4 亿 (图像, 文本) 对训练图像编码器 + 文本编码器，各自输出一个向量；
  • 训练后，两个编码器的输出落在同一个语义空间 —— 图像向量和"它的描述"的文本向量天然接近；
  • 副产品：零样本分类 —— 把 "a photo of a {类别}" 的文本向量和图像向量比相似度即可分类，不需要分类头、不需要训练。

为什么 VLM 都爱用 CLIP 系编码器？

特征空间天然与语言对齐（训练时就见过文本），投影层学起来事半功倍；表征通用、开放词汇；开箱即用、冻结即可，省去昂贵的视觉预训练。

SigLIP：CLIP 的高效改进版（minimind-v 的选择）

改进点：

  • CLIP 用 softmax 对比损失：需要全局归一化，大 batch 才稳定；
  • SigLIP 改为 sigmoid 逐对二分类损失：每对图文独立判断"配/不配"，小 batch 也稳定，训练更高效；
  • SigLIP2 进一步加入自蒸馏、多分辨率等技巧，是当下 VLM 最常用的视觉骨干之一。

minimind-v 的具体选型：siglip2-base-p32-256-ve

  • ViT-B/32 架构，~95M 参数，全程冻结，只做特征提取；
  • 256×256 输入 → 64 个 patch token → 输出 64×768 特征；
  • 只取 encoder 层输出（不需要它最终的对比学习嵌入向量）。

一个值得想的问题

SigLIP 训练的目标是"整图 ↔ 整段文本"的对齐，输出里每个 patch token 却携带着局部信息。VLM 复用它的 patch 级特征而不是整图向量 —— 为什么这样也行得通？（提示：注意力让 patch 之间交换过信息，且投影层与后续微调会进一步适配。）

分辨率是硬约束

256×256、64 个 token 意味着每个 token 管 32×32 像素的区域。小目标、图中文字在这个尺度下已经模糊 —— 这直接限制了检测定位精度与 OCR 能力（后面改进方向会再遇到它）。

② 投影层：把视觉特征"对齐"进语言空间

Projector 的职责：把视觉 token 的维度与分布映射到文本 embedding 所在的空间，让两种 token 可以在同一空间里被同一个 Transformer 处理 —— 这一步叫跨模态特征对齐。

方案演进：

  • LLaVA-1：单层线性变换 —— 简单有效；
  • LLaVA-1.5：2 层 MLP（Linear→GELU→Linear）—— 更强，成为事实标准；
  • BLIP-2：Q-Former，用少量可学习 query 把视觉信息压缩成固定数量的 token；
  • minimind-v：LayerNorm + 2 层 MLP（同 LLaVA-1.5 方案），~1M 参数。

Projector 参数极少，却是 VLM 里第一个被训练、且必被训练的模块。

先补一个概念：什么是"微调"（Fine-tuning）

迁移学习的直觉：

  • 预训练模型 ≈ 已经完成"通识教育"的毕业生：语言、常识、视觉表征都已具备；
  • 微调 ≈ 入职培训：用少量领域数据、较小的学习率、较少的步数，让它适应具体岗位；
  • 为什么不从头重训？数据贵、算力贵，而且会破坏已有能力（灾难性遗忘）。

微调的关键设计问题只有一个：放开多少参数让它学？

力度可训参数特点
全参微调100%上限最高；数据/显存需求大，遗忘风险大
冻结部分层如只训首末层保住主干能力，折中常用
只训新增模块如 Projector原模型零损耗，适配能力有限
LoRA低秩旁路矩阵（<1%）显存友好、可插拔，工业界标配

格式、坐标系、精度全部未定义		"定位图中的狗，输出 [x1,y1,x2,y2]，0~1 归一化，保留 3 位小数。"

① 输出格式显式化

模板、单位、小数精度都写进指令，解析器才有据可依。

② 答案空间封闭化

能做"选择题"就不做"开放题" —— 指标更客观，失败率更低。

③ 训练评测一致化

微调数据用的 prompt 必须与评测时同分布，否则指标失真、结论无效。

路线 A：零样本分类（不训练，先跑通）

做法：直接设计 prompt，把候选类别写进去，让模型"做选择题"：

[飞机, 汽车, 鸟, 猫, 鹿, 狗, 青蛙, 马, 船, 卡车]

04 · 检测

检测：坐标也是文本，让模型"说出"框

核心思想：边界框的 4 个坐标，不过是 4 个数字 —— 数字也是 token，模型可以像说话一样把框"说"出来（Qwen-VL 与各类 Grounding 模型的标准做法）。

用户: <image>\n找出图中的狗，输出边界框，
格式 [x1,y1,x2,y2]，0~1 归一化。
助手: [0.122, 0.341, 0.563, 0.782]
  • 坐标归一化到 0~1（或 0~999 整数），与图像分辨率解耦；
  • 多目标：输出多个框，框与类别名配对；
  • 此即视觉定位（Visual Grounding）：给文本描述，定位对应目标。
pred [0.20,0.32,0.66,0.90]
gt [0.26,0.38,0.62,0.86]

预测框 vs 真值框 → 算 IoU → Acc@IoU≥0.5

预期与心态

65M 小模型 + 256² 低分辨率，坐标不可能很准。看到"微调后 IoU 显著上升、框大致落在目标区域"就是成功。想一想：64 个视觉 token、每个管 32×32 像素，这个粒度如何限制定位精度？

  • 检测强化阶段（追加 det+locate 数据）提升检测与 locate 题，分类几乎不漂移；
  • 视觉编码器空间分辨率是检测瓶颈：P32 每 token 管 32×32 像素，小物体定位不准；换 P16（token 数 ×4）框明显更紧致；
  • 同类预测去重（NMS 式）能去掉重复框带来的 FP，评测脚本的解析与匹配同样影响指标。

微调要点与建议的对比实验

微调要点：

  • 基座选择：从 llm（纯语言权重）起步，或在官方 sft_vlm 上继续微调（推荐，省一轮对齐）；

避坑指南：六个高频问题

模型答非所问 / 不守格式

检查 prompt 是否与训练时表述一致；微调数据里答案格式是否统一；<image> 占位符是否漏写。

微调后反而"变傻"

典型灾难性遗忘：任务数据占比过高或 lr 过大。改 --freeze_llm 1/2、混入通用对话数据、降 lr。

检测坐标完全不对

先确认输出格式正确（能解析出 4 个数）再谈精度；检查归一化约定；256² 分辨率下小目标本就难，属预期现象。

重复啰嗦 / 停不下来

小模型常见。调低 temperature、增大 repetition_penalty（如 1.2）；也是错误分析的好素材。

显存不足

减小 batch_size + 梯度累积；缩短 max_seq_len；确认视觉编码器已冻结。

数据格式踩坑

用仓库 dataset/lm_dataset.py 预览自己的 parquet 前 5 条；确认列名、role 字段、图像字节流与官方样例一致。
